# BT-J2ME — концепт

Лёгкий нативный движок для запуска J2ME-игр (MIDP 2.0 / CLDC 1.1) на Linux:
минималистичный интерфейс, игра на весь экран, работает на слабом и старом железе
любой разрядности.

## 1. Цели

| Цель | Конкретная планка |
|---|---|
| Лёгкость | бинарник < 1 МБ, ОЗУ < 16 МБ на типичную игру 240×320 |
| Старое железо | Pentium II 300 МГц / 64 МБ ОЗУ, ARMv6 (Raspberry Pi 1) |
| Разрядность и архитектуры | i386/i586, x86_64, armhf, aarch64, mipsel; big-endian тоже |
| Минимум зависимостей | libc + zlib + SDL2; позже — бэкенд fbdev без X11 |
| Полный экран | масштаб с сохранением пропорций, по умолчанию только целые множители |
| Минимализм | нет рамки телефона, нет меню поверх игры: только игра и чёрные поля |

Чего **не** делаем: точную эмуляцию конкретного телефона, Bluetooth/SMS/камеру,
3D-API (M3G/JSR-184) — на первом этапе.

## 2. Язык: C99

Почему C, а не Java, Rust или C++:

- **Java** (как FreeJ2ME) требует JRE: +100–200 МБ и прогрев JIT. На старом ПК это
  дольше и тяжелее, чем сама игра. Цель проекта — как раз уйти от JVM хоста.
- **Rust** хорош, но i586/старые ARM поддерживаются по остаточному принципу,
  компилятор тяжёлый, а собрать на самом старом ПК не получится.
- **C++** не даёт ничего критичного для интерпретатора, но добавляет libstdc++.
- **C99** собирается любым gcc начиная с 4.x, под любую архитектуру, через одну
  строку `make CROSS=...`. Именно на C написаны эталонные маленькие VM
  (KVM от Sun, phoneME), а интерпретатор байткода — классическая задача для C.

Правила кода: без глобальных зависимостей кроме libc/zlib/SDL2, чтение чисел
только побайтно (`util.h`) — так код не зависит от порядка байт; никаких
предположений о размере указателя (32/64 бита).

## 3. Архитектура

```
 ┌──────────────────────────────────────────────────────────┐
 │  Лаунчер: полка CD-боксов (launcher.c, library.c)         │
 └───────────────┬──────────────────────────────────────────┘
                 │ JAR / JAD
 ┌───────────────▼──────────┐   ┌───────────────────────────┐
 │ Загрузчик                │   │ Нативный MIDP 2.0 на C     │
 │  jar.c      ZIP + zlib   │   │  lcdui: Canvas, Graphics,  │
 │  manifest.c MANIFEST/JAD │   │   Image, Font, GameCanvas, │
 │  classfile.c class-файлы │   │   Sprite, TiledLayer       │
 └───────────────┬──────────┘   │  rms: RecordStore → файлы  │
                 │              │  media: тоны/MIDI/WAV       │
 ┌───────────────▼──────────┐   │  Nokia UI, Siemens/SE API   │
 │ VM (CLDC 1.1)            │◄──┤  (самые частые в играх)     │
 │  интерпретатор байткода  │   └─────────────┬─────────────┘
 │  куча + mark&sweep GC    │                 │
 │  зелёные потоки          │                 │
 └──────────────────────────┘                 │
 ┌────────────────────────────────────────────▼─────────────┐
 │ platform.h: кадровый буфер ARGB, ввод, время, звук          │
 │  platform_sdl2.c  — основной (X11, Wayland, KMSDRM)        │
 │  platform_null.c  — без экрана (CI, проверка JAR)          │
 │  platform_fbdev.c — план: /dev/fb0 + evdev, без X вообще    │
 └──────────────────────────────────────────────────────────┘
```

Ключевые решения:

1. **Свой интерпретатор вместо JVM хоста.** Игры J2ME — это CLDC: ~200 опкодов,
   без рефлексии, без JNI. Небольшой switch-интерпретатор на C справляется с
   играми на ПК 2000-х годов: сами телефоны были в 10–50 раз слабее.
2. **Библиотека MIDP — нативная, на C, а не байткод.** `Graphics.drawImage`,
   `Sprite.paint`, `TiledLayer` — горячие места. Реализуя их на C поверх
   буфера ARGB, получаем основную скорость без JIT.
3. **Зелёные потоки.** Игры создают 1–3 `Thread`. Один системный поток и
   переключение между Java-потоками по счётчику инструкций: никакой pthread-синхронизации,
   детерминизм, работает даже там, где потоки дорогие.
4. **Один кадровый буфер.** Ядро рисует в буфер размера экрана телефона,
   бэкенд масштабирует целиком. Поэтому масштаб, полноэкранность и поворот
   экрана — забота только платформенного слоя.
5. **Сохранения (RMS)** — обычные файлы в `~/.local/share/bt-j2me/<игра>/`.

## 4. Интерфейс: «консоль» с полкой CD-боксов

- Запуск сразу в полноэкранном режиме, курсор скрыт.
- **Меню — полка с играми в прозрачных пластиковых CD-боксах (jewel case).**
  Центральный бокс крупный, соседние меньше и притушены, плавная прокрутка,
  отражение на «глянцевом полу», звёздный фон и лёгкие строки развёртки ЭЛТ.
- **Обложки подгружаются** по одной за кадр, начиная с ближайших к выбранной,
  и плавно проявляются. Файл `<игра>.png` или `covers/<игра>.png`, иначе обложка
  собирается из иконки игры. Боковые боксы рисуются отдельной уменьшенной копией
  обложки, чтобы мелкий текст не «рвался».
- **Запуск**: диск выезжает из бокса, экран гаснет, диск крутится — «Загрузка…».
- Меню рисуется в пиксельном разрешении ~240 строк с **целым** множителем,
  подобранным под экран, — поэтому оно заполняет весь экран без полей и мыла
  (1366×768 → 455×256 ×3, 1920×1080 → 480×270 ×4, 800×600 → 400×300 ×2).
- Игры: экран телефона по центру; масштаб «авто» — целый, если он заполняет
  ≥85% высоты, иначе дробный (`--sharp` / `--smooth` — принудительно).
- Размер экрана телефона: из `Nokia-MIDlet-Original-Display-Size` / JAD,
  иначе 240×320; задаётся `-s 176x208` и т.п.
- Управление с клавиатуры и Xbox-геймпада (SDL GameController, горячее
  подключение, стик с гистерезисом), мышь — тачскрин. Таблица — в README.
- Никаких окон настроек — только конфиг-файл (позже).

## 5. Дорожная карта

| Этап | Содержание | Статус |
|---|---|---|
| 0 | Каркас: сборка, JAR/ZIP, манифест, разбор class-файлов, SDL2 на весь экран, раскладка клавиш | **готово** |
| 0.5 | Лаунчер-полка с CD-боксами и обложками, PNG-декодер, пиксельные шрифты с кириллицей, Xbox-геймпад | **готово** |
| 1 | VM: загрузка и связывание классов, куча, строки, массивы, исключения, интерпретатор всех опкодов CLDC | |
| 2 | `java.lang`/`java.util`/`java.io` из CLDC 1.1 (часть — нативно) + `run` запускает `startApp()` | |
| 3 | lcdui низкого уровня: Canvas, Graphics (поверх gfx.c), Image (png.c уже есть), Font (растровый) | первые игры |
| 4 | GameCanvas, Sprite, TiledLayer, RMS | большинство 2D-игр |
| 5 | Звук: тоны, WAV, MIDI (простой синтезатор) — Player, Manager | |
| 6 | Высокоуровневый lcdui (Form, List, Alert) в минималистичном стиле; Nokia UI API | |
| 7 | Бэкенд fbdev+evdev, конфиг-файл, пакеты .deb / статические сборки | |

Проверка совместимости на каждом этапе: набор реальных JAR-ов и команда
`bt-j2me info`, которая уже сейчас проверяет каждый класс в архиве.

## 6. Аналоги и отличие

- **FreeJ2ME / freej2me-plus** — Java, нужна JRE; хорошая совместимость, но тяжело.
- **J2ME-Loader** — только Android.
- **KEmulator, Sjboy** — Windows, закрытые.
- **phoneME / KVM** — референсные C-VM от Sun; ориентир по устройству,
  но объёмные и под GPLv2 с особенностями.

BT-J2ME — нативный, маленький, только Linux, только «запустить игру и играть».

## 7. Открытые вопросы

- Лицензия проекта (MIT/GPL) — решить до появления сторонних контрибьюторов.
- Стоит ли сразу заложить JIT-шаблоны для x86/ARM или ограничиться
  интерпретатором с суперинструкциями (предложение: только интерпретатор).
- Нужна ли поддержка 3D (M3G) — сильно увеличивает объём, предложение: нет.
